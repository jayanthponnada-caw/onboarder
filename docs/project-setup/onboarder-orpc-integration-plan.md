# Onboarder oRPC and OpenAPI Setup

_Last verified: 2026-06-01_

## Goal

Keep the repository's split architecture:

```txt
apps/web                TanStack Start UI and SSR
apps/core               Hono API service
packages/api-contract   oRPC contract and shared schemas
packages/db             Drizzle/Postgres access
```

The API contract is shared, but the server implementation stays in `apps/core`.
Browser and SSR code in `apps/web` must not import Hono, Drizzle clients, database
drivers, server environment parsing, or Inngest function implementations.

## Current Data Flow

```txt
apps/web route/component
  -> TanStack Query / TanStack DB helpers
  -> createTanstackQueryUtils
  -> oRPC client
  -> OpenAPILink
  -> Hono /api/*
  -> OpenAPIHandler
  -> apps/core/src/orpc/router.ts
  -> @repo/db
  -> Postgres
```

There is intentionally no `/rpc/*` route in the current app. oRPC's `RPCHandler`
and `RPCLink` use oRPC's proprietary RPC protocol, which is not OpenAPI-compatible.
This project uses `OpenAPIHandler` and `OpenAPILink` so the same contract powers
the web client and generated API docs.

## Route Surfaces

### OpenAPI-compliant oRPC routes

These are generated from contract procedures that call `.route(...)` in
`packages/api-contract` and are handled by `OpenAPIHandler` in `apps/core`.

Current examples:

```txt
GET   /api/users
GET   /api/users/{id}
POST  /api/users
```

Docs and schema endpoints:

```txt
GET /api/docs
GET /api/openapi.json
GET /openapi.json
```

Use `/api/docs` for the interactive OpenAPI reference. `/openapi.json` is a
convenience static spec endpoint generated by `apps/core/src/openapi.ts`; the
OpenAPI Reference plugin also exposes `/api/openapi.json` through the oRPC
handler because the plugin is mounted with the `/api` prefix.

### Operational Hono routes

These are regular Hono routes and are not generated from the oRPC contract:

```txt
GET /health
GET /db/health
GET /auth/health
```

They are useful for runtime checks, local debugging, and deployment probes. They
are not part of the generated OpenAPI client unless they are explicitly moved
into the oRPC contract later.

### Inngest route

```txt
GET  /inngest
POST /inngest
PUT  /inngest
```

This route is intentionally outside the `/api` URL prefix because it is not an
oRPC API. It is Inngest's serve endpoint. Inngest uses the HTTP methods
differently:

- `GET` returns function metadata and development diagnostics.
- `POST` invokes functions.
- `PUT` registers functions with Inngest.

Keep `/inngest` separate from the broad `/api/*` OpenAPI middleware in Hono.
That keeps the endpoint out of Clerk-protected oRPC routing and out of the
generated OpenAPI client.

## Hono Mounting Model

`apps/core/src/index.ts` builds one Hono app:

1. Plain health routes are registered first.
2. `/inngest` is registered as a dedicated Inngest serve endpoint.
3. `/api/*` CORS middleware is applied for OpenAPI oRPC traffic.
4. `/api/*` Clerk middleware reads the session token.
5. `/api/*` forwards matching requests into `OpenAPIHandler` with `prefix: "/api"`.

Hono runs middleware and route matching in registration order. Keep more specific
operational routes, such as `/inngest`, separate from broad `/api/*` middleware.

## Contract Package

`packages/api-contract` owns:

- shared Zod schemas;
- oRPC contract definitions;
- exported contract and client types.

Example:

```ts
export const usersContract = {
	list: oc
		.route({
			method: "GET",
			operationId: "listUsers",
			path: "/users",
			summary: "List users",
			tags: ["Users"],
		})
		.input(ListUsersInputSchema)
		.output(z.array(UserSchema)),
}
```

The contract package must stay implementation-free. Do not import Hono, Clerk
middleware, Drizzle clients, database drivers, Inngest functions, or environment
parsing there.

## When `.route()` Is Required

Use `.route(...)` for every procedure that should be a stable OpenAPI HTTP
endpoint or appear cleanly in generated docs.

`.route(...)` defines the public HTTP shape:

- method;
- path;
- path parameters;
- operation id;
- summary;
- tags.

Without `.route(...)`, `OpenAPIHandler` can still infer default routing for some
procedures, but those defaults are less deliberate. In this repository, prefer
`.route(...)` for user-facing API endpoints so the URL shape and docs are stable.

It is acceptable to skip `.route(...)` for internal-only procedures only if they
are not part of the public OpenAPI surface and you are deliberately relying on
oRPC's default routing. If an endpoint is documented, consumed externally, or
expected to remain stable, add `.route(...)`.

## Core Implementation

`apps/core/src/orpc/router.ts` implements the contract:

- `implement(contract).$context<ORPCContext>()` binds the shared contract to a
  Core-only context.
- Each handler receives `context.auth`, `context.db`, `context.inngest`,
  `context.headers`, and `context.request`.
- Protected procedures call `requireUserId(context.auth)`.
- Side effects, such as `context.inngest.send(...)`, stay in Core.

`apps/core/src/openapi.ts` owns generated API documentation configuration:

- `ZodToJsonSchemaConverter` converts shared Zod schemas to JSON Schema.
- `openApiSpecOptions` defines shared schemas, bearer auth, API title/version,
  and the `/api` server URL.
- `createOpenApiDocument()` generates and caches the OpenAPI document.

`apps/core/src/index.ts` owns the Hono adapter:

- `OpenAPIHandler(router, ...)` handles OpenAPI-compatible oRPC traffic.
- `SmartCoercionPlugin` converts OpenAPI path/query/header string values into
  schema-compatible input values where possible.
- `OpenAPIReferencePlugin` serves `/api/docs` and `/api/openapi.json`.
- `onError(...)` logs oRPC handler errors.

## Web Client

`apps/web/src/lib/orpc.ts` uses:

```txt
OpenAPILink(contract, { url: `${origin}/api` })
createORPCClient(link)
JsonifiedClient<AppClient>
```

Use `JsonifiedClient` with `OpenAPILink` because OpenAPI traffic is JSON over
HTTP. Values such as `Date` may arrive as strings on the client, so UI-facing
model helpers should tolerate the JSONified shape.

Browser requests attach a Clerk bearer token when `window.Clerk.session` is
available and use `credentials: "include"`. SSR requests forward the incoming
request headers with TanStack Start's `getRequestHeaders()`.

## Plugin Notes

### Smart coercion

OpenAPI path and query values arrive as strings. `SmartCoercionPlugin` uses the
configured JSON Schema converters to coerce values into the schema's expected
types when possible. This improves developer experience for routes like
`/api/users/{id}` where `id` is a number in the schema but a string in the URL.

The tradeoff is runtime overhead. Keep it while the API is small and schema
correctness matters more than raw speed. If a hot path becomes measurable, move
coercion into explicit schemas or handlers and remove the plugin from that path.

### OpenAPI reference

`OpenAPIReferencePlugin` serves the browser documentation UI and the generated
spec through the same `OpenAPIHandler`. It should remain in Core because Core is
the source of the implemented router and runtime OpenAPI document.

### Zod schema converter

`ZodToJsonSchemaConverter` bridges the shared Zod schemas in
`packages/api-contract` to OpenAPI JSON Schema. Add converters here if the
contract package later adopts another schema library.

## Guardrails

- Do not reintroduce `/rpc/*` unless the project explicitly chooses to give up
  OpenAPI-compatible transport for that surface.
- Do not mount `RPCHandler` and `OpenAPIHandler` for the same contract unless
  there is a clear migration plan and test coverage for both transports.
- Do not add Inngest functions to the oRPC contract. Trigger Inngest from Core
  handlers, or expose dedicated non-oRPC operational routes if needed.
- Do not protect `/inngest` with Clerk session middleware; Inngest uses its
  own signing and registration flow.
- Do not import server implementation code into `packages/api-contract` or
  `apps/web`.
